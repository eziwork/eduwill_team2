# 고객 브리핑 콘텐츠 골격

이 골격으로 JSON 입력과 리포트 문장을 준비한다. 고정한 의사결정 질문에 도움이 되지 않는 페이지는 제거한다.

## 표지

- 거래유형과 고객 관점
- 제목이 되는 고객 질문 하나
- 한 문장 분석범위
- 대상명·주소와 면적·호실
- 기준일
- `actual` 또는 `demo` 표시
- 부동산 이미지와 선택적 정적 지도
- 중개사 브랜드 또는 EZIWORK 임시 로고

## 의사결정 개요

- 핵심 지표 3개
- 가격·비용, 계약조건, 미해결 위험을 분리한 한 문단
- `한눈에 설명` 한 개

## 근거 페이지 1

- 짧은 질문형 제목
- 한 문장 답변
- 차트 또는 지도 하나
- 출처·단위·기준일 설명
- 해석
- 한계 또는 다음 확인사항
- `한눈에 설명`

## 근거 페이지 2

추이, 대안, 권리, 총비용, 적합성, 불확실성 중 두 번째 판단축을 같은 구조로 작성한다.

## 계약 전 확인표

고객의 결정을 바꿀 수 있는 항목만 기록한다. 각 항목에는 다음을 둔다.

- 확인 제목
- 중요한 이유 또는 대조할 내용
- 가능한 경우 상태: `확인`, `추가 확인`, `판단 보류`

## 결론

제목은 `이번 분석을 정리하면`으로 한다.

- 짧은 요약 2문단
- `핵심 판단`
- `확인할 사항`
- `다음 행동`
- 짧은 면책문구
- 중개사 브랜드·로고

## 출처목록

근거그룹마다 출처 ID·등급, 출처명, 원문 URL 또는 내부기록 표시, 기준일, 조회범위, 한계를 기록한다. 고객 문서에는 근거가 표시된 페이지 가까이에 출처를 배치하고, 전체 목록은 내부 QA 기록에 보존한다.

## 기계 검증 연결

`actual` 리포트를 출력하기 전 다음을 확인한다.

- `target.claim_ids`와 `customer.claim_ids`를 추가한다.
- 지표와 확인항목마다 `claim_id` 하나를 연결한다.
- 개요, 모든 섹션·시각자료, 결론에 `claim_ids`를 연결한다.
- 요약카드마다 `claim_id` 하나를 연결한다.
- `references/evidence-audit-schema.md`에 따라 모든 주장, 계산, 근거그룹, 출처, 파일경로, SHA-256을 등록한다.
- 배포상태는 근거감사가 산출하므로 사람이 선택한 `release_status`는 넣지 않는다.

연결된 주장과 해시 검증 계산입력으로 뒷받침되지 않는 고객용 숫자는 배포 차단 오류다.
