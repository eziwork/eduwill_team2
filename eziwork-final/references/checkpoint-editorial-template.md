# 체크포인트 편집형 아파트 템플릿

## 지위

아파트 매매 리포트의 표준 경로다. 고객 질문이 아파트 매수 또는 매도라면 기본으로 사용한다. 사용자가 다른 디자인을 명시적으로 요청하지 않는 한 과거 실험 템플릿으로 교체하지 않는다.

기준자료:

- `assets/checkpoint-editorial-reference.html`: 수정 가능한 HTML과 정확한 시각기준
- `assets/checkpoint-editorial-reference.pdf`: 페이지별 비교를 위한 9페이지 출력기준

기준파일은 배치와 어조만 정의한다. 그 안의 단지명, 이미지, 지도, 숫자, 날짜, 결론은 예시이며 다른 리포트의 근거가 아니다.

## 고객 관점

한 고객 리포트에는 하나의 관점만 사용한다.

| 관점 | 고객 질문 | 의사결정 출력 |
|---|---|---|
| `BUY` | 지금 이 가격에 사도 괜찮은가 | 검토가격 위치, 대체매물, 협상 시작점·상한, 확인조건, 중단조건 |
| `SELL` | 지금 얼마에 내놓고 언제 조정할 것인가 | 출시가격, 경쟁매물, 반응 관찰기간, 조정구간, 유지·조정 조건 |

BUY와 SELL은 대상필터, 실거래, 공개매물 표본, 계산, 지도, 네 가지 근거모듈을 공유한다. 질문표현, 해석, 최종판단, 다음 행동만 바꾼다. 하나의 고객 PDF에 BUY·SELL 결론을 섞지 않는다.

## 고정 9페이지 순서

기본은 정확히 A4 세로 9페이지다. 실제 근거공백 또는 사용자 지시가 있을 때만 페이지를 더하거나 줄이고 QA 기록에 사유를 남긴다.

1. **표지** — 리포트 시리즈, 단지명, `분석 리포트`, 고객 관점, 건물이미지, 이미지 출처
2. **프롤로그 1** — 고객의 실제 질문, 실거래와 현재 공개매물을 나눠야 하는 이유
3. **프롤로그 2** — 넓은 가격질문을 구체적 행동으로 바꾸는 네 가지 근거모듈
4. **대상과 지도** — 단지 식별정보, 주소, 세대·면적 범위, 정적 지도, 간결한 제원표
5. **가격 위치** — 검토가·출시가를 체결 실거래와 현재 공개호가 범위에 비교
6. **개별 실거래 분포** — 분산, 이상값, 비교조건 주의, 잠정자료
7. **거래 활력** — 월별 거래건수와 중심가격, 0건 월도 유지
8. **현재 경쟁매물** — 대표 공개매물, 층·조건, 중복광고 한계
9. **결론** — 건물이미지와 짧은 편집형 5문단, 판단구간, 남은 확인사항, 다음 행동, 브랜드

분량을 늘리기 위한 일반 입지·학교·출퇴근·편의시설 페이지는 넣지 않는다. BUY·SELL 결정을 실제로 바꾸고 근거가 등록된 경우에만 추가한다.

## 근거 페이지 구성계약

1. 검은색 `PART` 표시
2. 보통 두 줄 이내의 짧은 파란 질문제목
3. 지도 또는 차트 하나
4. 출처·단위·기준일 설명
5. 결정적 숫자를 강조한 한 문장 답변
6. 파란색 소제목 하나
7. 해석 한 문단
8. 왼쪽 파란 선이 있는 `한눈에 설명`
9. 바닥글 위 작은 출처·한계 주석

`한눈에 설명`에는 결과를 직접 적는다. `고객에게는 이렇게 설명합니다`처럼 내부 영업대본을 드러내는 표현을 쓰지 않는다.

## 공통 근거모듈

### 1. 가격 위치

- 입력: 비교 가능한 체결 실거래, 검토가·출시가, 현재 공개호가 범위
- 계산: 체결가격 중심, 절대 차이, 차이율, 공개호가 범위 내 위치
- 체결 실거래와 현재 공개호가를 평균내지 않는다.
- BUY 질문: `지금 [검토가], 사도 괜찮을까요?`
- SELL 질문: `지금 [출시가], 어떻게 내놓을까요?`

### 2. 개별 실거래 분포

- 입력: 계약일, 가격, 면적, 층, 거래방식, 취소·잠정 상태
- 비교 가능한 모든 기록을 표시하고 당월·미확정 자료는 잠정으로 표시한다.
- 최고·최저 한 건이 아니라 비교조건을 통해 분포를 해석한다.

### 3. 거래 활력

- 입력: 월별 거래건수와 중위값 또는 명시한 강건한 중심값
- 완결기간끼리만 비교하고 0건인 월도 보인다.
- 최근 미완결월만으로 회복·둔화를 확정하지 않는다.

### 4. 현재 경쟁매물

- 입력: 단일 대상에 제한한 네이버페이 부동산 공개매물 확인, 대표 호가, 동·층, 조건메모, 관찰 광고건수, 조회시각
- 광고건수는 고유 매물건수와 다를 수 있음을 표시한다.
- 더 낮은 호가는 실제 판매가능 여부와 조건을 확인한 후에만 협상 참고가 된다.

## BUY·SELL 문구 분기

| 위치 | BUY | SELL |
|---|---|---|
| 표지 관점 | `매수 검토` | `매도 전략` |
| 프롤로그 질문 | 이 가격에 사도 되는가 | 어느 가격에 내놓고 언제 조정할 것인가 |
| 가격 해석 | 가격차이를 설명할 조건과 대체매물 | 출시가격의 경쟁력과 매수인이 비교할 대상 |
| 경쟁매물 해석 | 더 저렴한 대안·협상근거 | 더 저렴한 경쟁재고·반응저하 위험 |
| 결론 행동 | 조건 확인, 최초 제안가·상한 설정, 조건 미충족 시 중단 | 출시가 설정, 정한 기간 문의·방문 관찰, 정한 규칙으로만 조정 |

어조는 차분하고 설명형·편집형으로 쓴다. 기본 어미는 `확인됩니다`, `비교할 수 있습니다`, `추가 확인이 필요합니다`다. 전망, 압박, 감정평가 표현, 근거 없는 최상급을 피한다.

## 디자인 토큰

- A4 세로, 전면구성
- 기본 파랑 `#2c61ef`, 진한 파랑 `#1742a6`, 강조 산호색 `#ef6a4a`, 본문 `#17191d`
- 내지 주제목 약 `25pt`, 표지 제목 약 `40pt`, 본문 약 `10.5pt`와 넉넉한 행간
- 내지 여백 약 `18~20mm`
- 표지 상단 파란 영역 약 `164mm`, 건물이미지 약 `133mm`
- 근거 페이지당 차트 하나. 체결근거는 파랑, 제시가·현재 호가는 산호색, 잠정자료만 분홍색을 사용한다.
- 바닥글 왼쪽에 리포트명·단지명, 오른쪽에 두 자리 쪽번호를 둔다.
- 표지·결론 하단의 EZIWORK는 임시 브랜드다. 중개사 로고로 바꿀 때 비율을 유지한다.

## 지도·이미지 규칙

- 사용자 제공 실제 건물이미지 또는 출처·URL·캡처일이 있는 적법한 재사용 이미지를 사용한다.
- PDF에는 실제 정적 지도 화면이나 내보내기 이미지를 사용한다. 검색창, 측면목록, 확대버튼, 이동조작을 제외하고 필요한 제공자 표시는 유지한다.
- 인쇄물에 iframe을 넣지 않는다.
- `actual`에서 건물·지도 이미지가 없으면 배포조건으로 남기고 실제 촬영사진처럼 이미지를 조작하지 않는다.
- `demo`에서는 모든 페이지에 `교육용 예시 · 실제 시세가 아님`을 표시한 경우에만 생성 자리표시자를 허용한다.

## 데이터 출처 계약

- 체결 실거래: 부동산 유형에 맞는 공식·공개 거래기록. 원문 URL·조회, 필터, 조회일, 제외내역, 잠정상태를 기록한다.
- 현재 매물: 사용자가 실행한 단일 대상·제한적 네이버페이 부동산 확인. 조회시각, URL, 대상필터, 관찰건수, 중복처리, 확인불가 행을 기록한다.
- 지도와 사진은 각각 별도 출처로 등록한다.
- 비공개 확인은 `내부 확인 기록 · 외부 링크 없음`, 확인일, 확인자 역할을 기록한다.
- 모든 표시지표와 결론은 출처 ID에 연결하고 계산값은 재현 가능한 계산 레코드에도 연결한다.

## 생성과 QA

`assets/checkpoint-editorial.example.json`과 `scripts/build_checkpoint_report.py`를 사용한다. 생성기는 기준 HTML의 CSS와 내장 차트 런타임을 가져오고 모든 대상 콘텐츠·차트자료를 교체한 뒤 공통 근거감사를 실행하며, 감사결과가 `HOLD`이면 생성을 거부한다.

PDF 출력 후 9개 페이지를 기준 PDF와 비교한다. 페이지 순서, 글자크기, 이미지 자르기, 지도 표시, 차트 4개, 출처주석, 바닥글, 예시표시, 결론 리듬을 확인한다. 디자인 유사성이 예시데이터 복사나 근거 없는 주장을 정당화하지 않는다.
